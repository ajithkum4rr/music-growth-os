# music-growth-os

A practical, independent Music Growth Operating System for `ajkay`.

This repository is a real-world framework for building a sustainable artist marketing engine without relying on shady growth hacks or agency black boxes.

## What this is

- A step-by-step system for an independent music artist.
- Built around legitimate audience research, content, marketing, analytics, and release execution.
- Designed to be executed by one person.
- Focused on learning, measuring, optimizing, and repeating.

## What this is not

- Not a quick-fix playlist farm.
- Not a fake-stream or bot strategy.
- Not agency jargon without practical execution.
- Not a complex software platform. It starts simple.

## How to use this repo

1. Read `USAGE-GUIDE.md` for the full repo workflow, including manual execution, agent guidance, and automation.
2. Read `README.md` for the overview.
3. Read `MASTER-PLAN.md` for architecture and phase dependencies.
4. Use `ROADMAP.md` to plan the next 6–8 weeks.
5. Work phase-by-phase inside `/docs`.
6. Track progress with `/checklists` and `/templates`.

## Repo structure

- `README.md` — project overview and instructions.
- `MASTER-PLAN.md` — system architecture, phase dependencies, and execution strategy.
- `ROADMAP.md` — short-term time-based plan.
- `/docs` — phase-level SOPs and playbooks.
- `/sops` — reusable standard operating procedures.
- `/templates` — campaign, outreach, and asset templates.
- `/checklists` — phase checklists and execution lists.
- `/research` — audience, market, and campaign research notes.
- `/campaigns` — release plans, creative briefs, and results.
- `/analytics` — metrics definitions, dashboard design, and reports.
- `/experiments` — experiments, hypotheses, results, and learnings.
- `/agents` — AI agent definitions, roles, and workflows.
- `/rag` — retrieval-augmented generation architecture and source design.
- `/scripts` — automation helpers, data exports, and reporting scripts.
- `/data` — simple CSV/JSON records and tracking tables.

- Do not implement paid or risky automation until the system has a stable foundation.
- Keep all account credentials out of this repo.
- Use `.env.example` for any future API/service keys.
